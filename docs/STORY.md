## 면접 답변 틀
- **무엇을 만들었나:** 위 한 문장.
- **왜 이렇게 설계했나:** `docs/DECISIONS.md`의 ADR 하나당 한 문장씩. 특히 ADR-018(호출 단계 거절), ADR-019(게이트웨이), ADR-020(서버 소유 정책·저장된 체인), 이 문서의 평가·누락 검사.
- **본인이 한 것:** 무엇을, 왜 만들지와 품질 기준(정직한 데모 표시, 쿼리파이 관점, 학생 실사용)은 제가 정했고, 구현은 Claude Code와 짝으로 했습니다. 결과를 직접 실행해 보고 문제(날짜 밀림, 체인 재계산 허점, 놓친 마감)를 찾아 다시 시켰습니다.
- **한계:** 정규식 기반 민감정보 탐지, 체인 머리의 외부 고정 없음, 평가 세트가 작음(사람이 쓴 정답 28개), 실제 계정 검증은 GitHub 1회.

## 숫자 읽는 법
- "가린 개인정보 30" 같은 숫자는 **가린 횟수**입니다. 같은 전화번호가 계획 요청과 리포트 요청에 각각 들어가면 두 번 셉니다.
- 평가의 "리포트 8/9"는 정답 9개 중 리포트 문장이 직접 언급한 개수, "누락 검사 포함 9/9"는 리포트엔 없지만 누락 검사가 띄운 것까지 더한 개수입니다.
